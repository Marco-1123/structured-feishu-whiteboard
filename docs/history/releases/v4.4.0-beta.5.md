# V4.4 beta.5: systemic stability reset

## Why this release exists

Cross-Agent results diverged from local previews because the repository, installed Skill copies, and evaluation fixtures did not share one enforceable production contract. Historical renderers remained discoverable, prepared inventories bypassed raw-source extraction, and manifests did not identify the exact code and tools that produced an output.

## Production contract

- One production entry: `scripts/run-whiteboard-v44.mjs`.
- One production engine: V4 SVG.
- Raw material must first become a traceable `content-inventory.json`.
- Every fact requires `sourceRef`; critical and high-importance facts cannot be silently dropped.
- Agents produce JSON facts, not handwritten SVG or arbitrary layout choices.
- A run is deliverable only when its manifest reports `pipeline: "v4.4"` and `status: "passed"`.

## Stability changes

- Strict inventory schema and extraction contract.
- Semantic gates for flow, swimlane, comparison matrix, and repeated content.
- Flow node titles and body copy can no longer duplicate each other.
- Single-handoff material no longer becomes a decorative swimlane.
- A comparison matrix requires real comparison dimensions.
- Concise onepages reclaim accidental bottom whitespace without becoming long vertical canvases.
- Manifests record version, Git commit, tool versions, inputs, and output hashes.
- Preview-skipped runs are explicitly unverified and cannot masquerade as passed.
- The whiteboard renderer version is pinned for reproducible output.

## Validation boundary

Prepared inventories are regression fixtures only. They prove inventory-to-render behavior, not raw-material extraction quality. Cross-Agent acceptance must start from the same raw material and verify the resulting inventory, manifest, SVG, and Feishu preview.

## Release rule

Install or update from the immutable `v4.4.0-beta.5` tag. Branch URLs are not accepted for cross-Agent comparison because their contents can move over time.
