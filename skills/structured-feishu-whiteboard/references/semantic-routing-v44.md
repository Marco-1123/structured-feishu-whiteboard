# V4.4 语义路由

## 六类场景

- `review-update`：季度、半年度、年度、项目阶段、OKR 总结与下一阶段规划。
- `strategy-proposal`：战略判断、业务方案、资源取舍与验证。
- `project-plan`：目标、阶段、里程碑、依赖与交付。
- `research-decision`：调研、比较、选型与决策。
- `product-capability`：产品、工具、平台能力与使用机制。
- `process-collaboration`：审批、系统交互、跨团队或人机协同流程。

## 置信度

- 高：候选得分、领先幅度和必要信号均充分，自动选择。
- 中：自动选择最高分，同时在 `decision.json` 保留备选。
- 低：停止正式交付，返回候选和缺失信号；不得改走旧版本并伪装成 V4.4。

置信度来自事实证据，不来自 Agent 自报。指标支持结果驱动，阶段支持时间叙事，选项与评价维度支持比较，能力层级支持系统结构，多角色有序节点支持泳道流程。

## 模块可选性

- 只强制一个核心判断或主题锚点。
- 证据、风险和行动不是固定三件套，可以独立、合并、嵌入或不出现。
- 单条行动优先进入路线或流程；单条证据优先嵌入判断链或比较；单条风险优先成为状态或评价维度。
- 两个以上同类高优先级事实，或任一关键事实，才优先保留独立区域。
- 禁止为形成闭环而虚构内容或机械补齐模块。

## 组件选择

- 明确数值、单位或上下界：评估指标、进度、趋势、排名或差异桥。
- 输入、动作、判断、输出有明确连接：使用流程图。
- 阶段与里程碑有明确先后：使用路线或时间结构。
- 多对象与多维度：使用对比矩阵。
- 能力、状态和责任并列：使用状态板或能力结构。
- 原因、证据和行动构成论证：使用判断链与左右论证骨架。

## 完整性

- 关键和高优先级事实必须进入画板，或在遗漏台账记录明确原因。
- `sourceFactIds` 只能声明实际绘制的事实。
- 缺失信息可以标记待补充，不得编造。
- 相同事实不得同时以标题、正文和标签重复呈现。

## 正式入口

所有六类场景统一执行：

```bash
node scripts/run-whiteboard-v44.mjs --source <raw-source.md> --input <inventory.json> --output-dir <output-dir>
```

没有并行生产版本。旧代码只做回归与排障。
