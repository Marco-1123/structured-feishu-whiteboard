# V4.4 原始材料提取契约

V4.4 的稳定性从原始材料进入 `content-inventory.json` 时开始，而不是从 SVG 渲染时才开始。任何 Agent 都必须遵守本契约，不能先自由摘要、再把摘要包装成事实清单。

## 必做步骤

1. 完整读取用户提供的材料，不只读取标题、摘要或前若干段。
2. 将完整原材料原样保存为 source snapshot，并写入 `sourceRef`。网页和飞书文档使用原始链接；粘贴文本使用 `inline:<任务标识>`。摘要、节选或 Agent 自己改写的文本不能冒充 source snapshot。
3. 将材料拆成原子事实。一条事实只表达一个结论、指标、证据、风险、约束、阶段或行动。每条事实填写 `sourceQuote`，内容必须是 source snapshot 中能直接定位的原文片段。
4. 保留所有 `critical` 和 `high` 信息。不得为了缩短画板而删除关键结论、指标、证据、风险、约束或行动。
5. 合并同义重复，保留更具体、证据更完整的一条；不得让同一事实以不同措辞重复进入多个模块。
6. 数字、日期、比例、主体、因果和比较关系必须来自原材料。无法确认时标记为 `unresolved`，不得补写。
7. 流程事实只有在材料明确表达顺序、角色或交接时才填写 `order`、`actor` 和关系字段。
8. 运行正式入口时必须同时传入 `--source` 和 `--input`。脚本会检查事实数量、重要度、类型覆盖、数字召回和原文引用；失败时回到事实提取，不得绕过或改用旧渲染器。

## 禁止行为

- 只保留“看起来适合画图”的内容。
- 把一整段原文作为一条事实。
- 为凑齐证据、风险、行动等固定模块而虚构内容。
- 为了使用泳道图而猜测角色。
- 为了使用指标卡而把没有业务含义的数字包装成指标。
- 将没有来源标识的清单作为正式生产输入。
- 把 `sourceRef` 写成 `fixture:*` 绕过真实原文检查。该前缀仅限仓库内部测试代码显式开启。

## 交付判断

事实清单必须能够回答：画板中的每个重要结论来自哪里、哪些重要信息被选择、哪些信息被延后，以及为什么。脚本负责构图稳定性，Agent 对事实清单的真实性与完整性负责。
