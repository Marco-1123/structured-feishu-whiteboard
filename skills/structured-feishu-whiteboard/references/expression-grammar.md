# V4.4 Expression Grammar

本文件只描述当前正式生产链路。历史版本的表达语法不再参与 Agent 决策。

## 核心原则

1. Agent 只提交事实清单，不选择坐标、卡片数量或 SVG 写法。
2. 语义规划器先判断事实关系，再选择页面骨架和组件。
3. 渲染器负责二维构图、文字测量、间距和画布尺寸。
4. 质量门禁失败时修复事实映射或构图，不切换旧版本，也不手写 SVG。

## 表达模式

- `dashboard-onepage`：阶段复盘、经营复盘和指标状态。数字关系充分时使用。
- `narrative-map`：判断、原因、证据、取舍与验证路径。
- `modular-canvas`：能力、架构和多类事实混合，但仍需明确主次。
- `flow-canvas`：节点连接关系是核心信息时使用；支持线性流程和泳道流程。

## 组件资格

- `statement`：一个核心判断或主题锚点，最多 3 行。
- `metric-card`：必须有明确数值和业务含义。单指标进入主体网格，两个以上才形成独立指标带。
- `progress-bar`：至少 2 个同口径百分比或进度值。
- `ranked-bar`：至少 3 个可排序且同口径的数值。
- `trend-sparkline`：至少 3 个有顺序的时间点或阶段值。
- `variance-bridge-v2`：一个起点、一个终点和至少 2 个带正负号的变化因素。
- `status-board`：2–6 个并列状态、能力或关注点；颜色必须有语义。
- `narrative-chain`：2–5 个存在方向关系的判断节点。
- `mini-roadmap`：2–5 个有明确先后的阶段或里程碑。
- `decision-matrix`：至少 2 个选项和 2 个评价维度。
- `evidence-list`：只有重要证据不能自然嵌入主结构时独立出现。
- `risk-list`：只有明确风险或约束时出现。
- `action-list`：只有明确行动且未被路线或流程吸收时出现。

禁止为丰富页面而伪造数据组件。没有数值时不生成指标、趋势、进度或差异桥。

## 页面骨架

- `overview-detail`：结果或指标为主，主体优先 8:4，补充信息 6:6。
- `centered-system`：能力或系统结构为主，系统与路径优先并排，支持信息放在下一行。
- `past-future-split`：阶段路径为主，主路线 8 栏、关注点 4 栏；不得连续堆叠全宽横条。
- `left-right-argument`：判断链路与单指标可组成 8:4，证据与状态组成 6:6。
- `multi-line-comparison`：矩阵为主，推荐结论与约束作为侧栏或收束带。
- `timeline`：时间轴只占一个主要信息层，其余信息必须转为双列或短收束带。

## 全局构图

- 默认宽度 2200，正式 OnePage 宽高比 1.42–2.15。
- 核心判断之后优先 2 个主体信息层，复杂场景最多 3 层。
- 除真正的时间轴、流程轴和矩阵外，不允许连续两个稀疏全宽模块。
- 窄模块不得独占底部一行。无法配对时改为收束带、合并语义或铺满有效宽度。
- 短链路不自动占满整行；单指标不自动形成独立指标行。
- 同排组件只共享外框高度，不得因此把内部内容贴顶、贴底或留下单侧大空洞。

## 颜色语义

- 主色：普通信息、结构和中性状态。
- 绿色：明确完成、成功或正向结果。
- 棕红色：明确风险、警告、阻塞或待处理。
- 同一组并列指标默认使用同一主色；不能无理由突出其中一项。

## 失败条件

- 画布因模块数量不断向下延长。
- 页面底部出现孤立窄卡或大块无效留白。
- 所有关系都退化成白色描边卡片和文字列表。
- 指标标题因删数字形成残句，或标题、正文和标签重复同一句话。
- 文字出框、压线、重叠、裁切或字号过小。
- manifest 不是 `pipeline: structured-whiteboard` 且 `status: passed`。
